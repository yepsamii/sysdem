## Service worker

`/sw.js` is generated by `vite-plugin-pwa` and registered by `/registerSW.js`:

```js
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js', { scope: '/' })
  })
}
```

Strategy: standard vite-plugin-pwa precaching (HTML, JS bundles, CSS, icons, manifest).

## Fonts

| Family | Used as | How served |
|---|---|---|
| Inter | UI (`body`, `header`, buttons, nodes, dialogs) | Not bundled — falls back to system fonts. The CSS chain starts with `"Inter"` then `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, …`. Recreation should bundle via `@fontsource/inter` or link Google Fonts. |
| JetBrains Mono | Edge labels (animated protocol text), code, kbd | Same pattern: `"JetBrains Mono"` then `ui-monospace, "SFMono-Regular", Menlo, …`. Use `@fontsource/jetbrains-mono`. |

Verification: `document.fonts.size` is `0` immediately after navigation — no `<link>` or `@font-face` for these families was found in the loaded stylesheets, confirming they're loaded asynchronously or implicitly by the browser/OS.

## Implications for a reimplementation

- Mirror the favicon + manifest set exactly.
- Bundle Inter + JetBrains Mono locally (don't rely on system fallback for visual consistency).
- Treat the cloud catalog as JSON or a JS module — Vite can code-split it so it's only fetched when the user opens the cloud section.
- If you can't redistribute AWS/GCP/Azure icons, consider replacing them with neutral inline SVGs and adding an attribution page.
